# stripe、支付与风控

GPT、Claude、OpenRouter、Cursor、Grok 等主流 AI 服务都接入的是 Stripe，因此有必要研究其支付与风控。
这是近2年、500 余次付款总结的经验，按照 Stripe 主要支持的付款方式、主要服务逐项讲解，并持续更新。

**目录****：**银行卡 → 持卡信息 → 卡 BIN 与质量 → 网络 IP 与指纹 → 付款状态与排查。其他付款方式后续补充。

# 1\.0银行卡

## 1\.1 信息一致性

- 无影响：持卡人姓名、持卡人邮箱。

- 可能影响：账单地址。地址不一致多数情况下仍可通过，但可能累加风险值。

## 1\.2 卡 BIN 与质量

卡 BIN 可用于识别发卡机构、地区及卡种，可在 bincheck\.io 查询。质量排名如下：

- 账户类型：机构卡 ＞ 个人卡。

- 卡种：信用卡 ＞ 借记卡 ＞ 预付卡。

- 卡组织：万事达 ≈ Visa ≈ 国际银联 ＞ 中国银联。

- 发行地区：美国 ≈ 波多黎各 ≈ 新加坡 ≈ 瑞士 ＞ 澳大利亚 ＞ 香港 ＞ 中国。

## 1\.3 付款 IP 和环境

1. 误区：没有任何服务必须使用家宽，欺诈值足够低即可，静态机房 IP 即可稳定通过支付。

2. 要点：打开页面、拉取订阅、最终扣款三个阶段的 IP 必须一致，严禁漂移。

3. 重试与冷却机制：前 1—3 次重新尝试不影响通过；失败后，该卡会被拉黑约 3—6 小时，期间所有付款均无法通过，包括更换账号或服务。

4. IP 质量优先，无需与发卡国家、账单地址严格一致，一致更好。

5. 指纹：Stripe 在付款后能拿到指纹，并传递给服务提供商。例如 Cursor、OpenRouter 付款后一定会限制大陆用户模型访问；Claude 可能会累积风控（无证据）。

**网络质量排序：**家宽 ＞ 机房 ＞ VPN ＞ 无节点；静态节点 ＞ 活动节点 ＞ 公用节点。

## 1\.4 关于付款状态

- **3DS 验证：**环境没问题，卡片本身需要二次验证。

- **“付款不被批准”：**常见于 GPT 的地区限定优惠，卡片与地区不一致。

- **“您的付款被拒绝”：**最常见的报错，属于 IP 问题，按上面的注意事项排查即可。

- **“您的订阅被取消 / 您的账户被禁用”：**常见于 GPT、Claude 使用同一张卡为多个账号开通免费试用的场景，会导致所有相关账号被封禁。同一张卡用于多个账号购买正常付费或折扣套餐，属于合规使用，不受影响。

# 2\.0 其他支付方式

## 2\.1 Link

Stripe 的客户端支付产品。提前通过手机号绑定多张卡，付款时接收验证码后自动填充支付信息。

- 卡片信任度与限制：不会额外增加卡片信任度，也不能突破卡片临时封禁的限制。

- 信息留存：依旧能够传递和留存卡片信息。

## 2\.2 Apple Pay / Google Pay

提前将多张卡绑定到对应的钱包，付款时通过生物验证后自动填充支付信息。

- 卡片信任度与限制：不会额外增加卡片信任度，也不能突破卡片临时封禁的限制。

- 信息留存：依旧能够传递和留存卡片信息。

## 2\.3 PayPal

是否显示该支付方式与 IP 有关，仅英国、加拿大等部分国家支持。付款风控转为 PayPal 内部风控。

- 卡片信任度与限制：会改变卡片信任度，可突破卡片临时封禁的限制。

- 信息留存：不向服务商传递和留存卡片信息。

## 2\.4 微信 / 支付宝

仅 OpenRouter、Grok 等少数服务支持，无付款风控。

- 支付规则：不按照卡片信任度规则，所有卡、余额、抵用金均可支付。

- 信息留存：会留存支付状态，并判定为大陆用户。

- 服务限制：已知 Grok 暂无措施；Cursor 可能限制部分模型；OpenRouter 一定会限制部分模型。

## 2\.5 Crypto（加密货币）

支持的商家较少，使用 OKX Wallet 等钱包进行链上转账即可。

- 安全性：最高，需要具备加密货币基础。

- 管理难点：汇率混乱，组织充值难以统一管理。
