# 项目代码规范

沿用项目实际技术栈与检查命令，未知项写未配置。只记录适用的约束，不把模板视作已完成验证。

## 验证

- 低风险直接检查结果；业务/接口改动增加定向回归与相关套件；权限、迁移、并发等增加失败恢复及关键保证验证。
- bug 回归证明旧实现行为失败、新实现通过；回退或破坏检查在隔离副本进行。
- 真实平台行为须在对应环境验证；缺环境明确 NOT RUN。项目必需 CI 不能省略。
- 合并须独立审查并绑定实际候选；发布确认 CI 与真实产物。失败、取消或未运行不是通过。

## 一致性

产品和架构决定只在 DECISIONS.md 维护；此处引用对应决定，不重复复制。模块状态与接口的所有权应清楚，改动时核对实际调用者。保护用户数据与配置，读取失败不能转成权限放行。

## 从教训升级的规则

仅录入有证据的通用规则，附来源 lesson 链接；三日新实例后升级，重大风险可提前说明理由升级。
